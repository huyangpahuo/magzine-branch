# Magzine 主题图片压缩机制与 GitHub 工作流指南

> 本文介绍主题内置的图片压缩/WebP 转换机制的工作原理、配置方法,以及如何用
> GitHub Actions 自动构建部署。适用于任何使用 magzine 主题的 Hexo 站点。

## 一、压缩机制总览

压缩功能完全位于主题内(`themes/magzine/scripts/other/compress-images.js`),
不依赖任何仓库级配置,分享主题文件夹即可获得完整功能。唯一的运行依赖是
`sharp`(在站点根目录 `npm install sharp`)。

### 工作原理:路由流转换

Hexo 的一切输出(写盘、`hexo server` 预览、CI 构建)都经过**路由(route)流**。
本机制在 `after_generate` 钩子里包装这些路由,在数据流出时即时转换——

```
hexo generate / hexo server
        │
        ▼
┌─ 路由注册阶段(after_generate)─────────────────────┐
│  1. 扫描全部图片路由(png/jpg/jpeg/webp/avif/gif)     │
│  2. webp 模式:为待转换图片登记改名映射(.png → .webp) │
│  3. 包装图片路由:输出时走 sharp 压缩/转换(带缓存)    │
│  4. 包装文本路由(html/css/js/json/xml):输出时自动    │
│     把对已转换图片的引用改写为 .webp                  │
└──────────────────────────────────────────────────┘
        │
        ▼
┌─ 输出阶段(写 public / 响应预览请求)────────────────┐
│  图片流 → sharp → 压缩/WebP → 只有更小才采用,否则原图 │
│  文本流 → 正则改写引用(裸路径 + URL 编码两种形式)     │
│  转换结果按路径缓存(上限 400MB,近似 FIFO 淘汰)       │
└──────────────────────────────────────────────────┘
```

### 为什么这样设计

- **一次构建即生效**:旧方案扫 public 文件夹,但 `after_generate` 触发时文件
  还没写盘,必须连续跑两次 `hexo generate`;路由流方案不存在这个时序问题。
- **本地预览即所得**:`hexo server` 也走路由,预览看到的就是压缩后的效果。
- **CI 无关性**:任何构建环境(GitHub Actions / Vercel / 本地)自动生效。
- **引用零改动**:文章、主题配置、脚本里的 `.png/.jpg` 引用自动改写,
  不需要手动改成 `.webp`;转换失败自动回退原图。

## 二、配置说明(主题 `_config.yml`)

```yaml
compress_images:
  enable: true            # 总开关
  mode: "webp"            # "webp"(推荐)= png/jpg/jpeg 转 webp
                          # "keep"      = 保留原格式仅压缩
  convert: [".png", ".jpg", ".jpeg"]  # webp 模式下参与转换的扩展名
  max_width: 1920         # 宽度超过此值等比缩小;0 = 不限制
  min_size: 10240         # 小于 10KB 的图片不处理(压缩收益低)
  ignore: []              # 额外忽略的扩展名,如 ['.gif']
  protect:                # 这些路径前缀下的图片不转换也不压缩:
    - "/images/pet/"      #   桌宠精灵图(文件名在 JS 里动态拼接,
    - "/cursors/"         #   构建期无法可靠改写引用,故保护)
  quality:                # 压缩质量(0-100)
    jpeg: 80
    png: 80
    webp: 75
    avif: 60
    gif: 80
```

### protect 的适用场景

JS 运行时动态拼接路径的资源(如 `` `${base}halo.png` ``)无法在构建期改写
引用,必须放进 `protect`。默认保护了桌宠精灵图和自定义光标帧。

### 实际效果(本站实测)

- `public` 体积:**618MB → 177MB**(剩余大头是音乐 mp3 与文章 GIF)
- 807 张图自动转 WebP,268 个文本路由的引用自动改写,全站 24000+ 引用零断链
- 典型单图:12.6MB 封面 → 261KB;5.9MB 卡片背景 → 152KB

## 三、本地使用

```bash
npm install sharp        # 一次性
hexo clean               # webp 模式建议先 clean,避免 public 残留旧 .png
hexo generate            # 一次即可,构建日志会输出转换统计
hexo server              # 预览 = 压缩后效果(转换有缓存,二次请求毫秒级)
```

## 四、GitHub Actions 自动构建部署

仓库自带的 `.github/workflows/hexo-deploy.yml`(不属于主题,仅本仓库使用):

```yaml
on:
  push:
    branches: [main]        # ← 改成你的默认分支
  workflow_dispatch:        # 支持手动触发

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci                 # 安装依赖(含 sharp)
      - run: npx hexo clean         # 清理旧产物
      - run: npx hexo generate      # 构建 + 图片压缩/WebP 全自动
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with: { path: public }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

### 开通步骤(一次性)

1. 仓库 **Settings → Pages → Source** 选择 **GitHub Actions**;
2. 确认 `hexo-deploy.yml` 中 `branches` 与你的默认分支一致;
3. push 之后 Actions 自动构建,产物即压缩/WebP 后的 `public`。

### 常见问题

| 现象 | 处理 |
|---|---|
| Actions 里 sharp 安装失败 | `package-lock.json` 与 `package.json` 不同步,本地 `npm install` 后提交 lock 文件 |
| 部署后图片仍是 .png | 检查主题配置 `compress_images.enable: true`;确认工作流跑的是 `hexo clean + generate` |
| 某图片转换后模糊 | 调高对应格式 `quality`;复杂长截图建议单独提高 |
| JS 动态拼路径的图 404 | 把该目录前缀加进 `protect` |
| 想保留 gif 动图原样 | `ignore: ['.gif']`(gif 转换耗时长,默认也不在 convert 列表) |

## 五、机制速查

| 问题 | 答案 |
|---|---|
| 转换在哪发生 | 构建期(路由流),浏览器端零开销 |
| 高亮引擎 | hexo 内置(hexo-util 封装 highlight.js,服务端渲染) |
| 需要 hexo g 跑两次吗 | 不需要(旧版机制的问题,已重写) |
| server 预览是压缩后的吗 | 是,且有转换缓存 |
| 原图会被修改吗 | 不会,source/ 原图永不改动 |
| 分享主题给别人能用吗 | 能,机制全在主题内,对方只需 `npm i sharp` |
